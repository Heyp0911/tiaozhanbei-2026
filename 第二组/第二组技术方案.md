### 4.2 核心算法

**物理模型**（数据组已验证）：
```
T_cell(t) = T2M(t) + (NOCT - 20) / 800 × GHI(t)
P_pv(t)   = P_rated × (GHI(t) / G_STC) × [1 + k × (T_cell(t) - T_STC)]
P_pv(t)   = max(P_pv(t), 0)
```

**K-Means聚类**：
- 将365天×24h矩阵聚类为4类
- 聚类中心即为4条典型日曲线
- 每条曲线可对应气象场景（晴天高峰/多云中等/冬季低日照/阴雨低谷）

**波动性分析**（模块一新增，数据组未做）：
```python
对每条典型日曲线计算：
  daily_mean       = 日平均出力(MW)
  daily_std        = 标准差(MW)
  max_ramp_rate    = max(|P[t+1] - P[t]|)       # 最大爬坡率(MW/h)
  effective_hours  = count(P[t] > 0.1*P_rated)   # 有效发电小时数
  peak_valley_ratio = (P_max - P_min) / P_rated   # 峰谷差比
  ci_upper         = P[t] + 1.96*std             # 95%置信区间上界
  ci_lower         = P[t] - 1.96*std             # 95%置信区间下界
```

### 4.3 小水电出力构造（闽清验证专用）

闽清县是福建省小水电大县。根据公开资料，福建省径流式小水电的典型出力特征：

```
径流式小水电日出力模型：
  · 出力相对光伏更平稳，无剧烈波动
  · 夏季丰水期出力高（6-9月），冬季枯水期出力低（12-2月）
  · 日内变化缓慢，受上游来水影响，滞后于降雨
  · 典型出力模式：夜间70-80%额定值，日间根据调度微调

简化构造（丰水期典型日）：
  P_hydro[t] = P_hydro_rated × (0.7 + 0.2 × 调度因子[t])
  
简化构造（枯水期典型日）：
  P_hydro[t] = P_hydro_rated × (0.3 + 0.1 × 调度因子[t])

P_hydro_rated = 5 MW（假设值，基于闽清县公开小水电装机数据估算）
```

### 5.2 模型定义

#### 集合与索引
- $t \in \mathcal{T} = \{0, 1, 2, ..., 23\}$，时间步为1小时

#### 输入参数

| 符号 | 含义 | 来源 |
|------|------|------|
| $P_{pv}^{avail}[t]$ | 光伏可用出力(MW) | 模块一典型日曲线 |
| $P_{load}^{base}[t]$ | 县域基础负荷(MW) | 数据组基础负荷CSV |
| $P_{grid}^{max}$ | 电网最大购电功率(MW) | params.json |
| $P_{rigid}^{demand}[t]$ | 刚性任务固定需求(MW) | params.json构造(24h均匀) |
| $E_{elastic}^{daily}$ | 弹性任务日总能耗(MWh) | params.json |
| $E_{cold}^{daily}$ | 温冷任务日总能耗(MWh) | params.json |
| $P_{elastic}^{max}[t]$ | 弹性任务每小时上限(MW) | params.json(日总量×15%) |
| $P_{cold}^{max}[t]$ | 温冷任务每小时上限(MW) | params.json(日总量×15%) |
| $P_{node}^{rated}$ | 节点额定功耗(MW) | params.json |
| $P_{node}^{idle}$ | 节点空闲功耗(MW) | params.json |
| $E_{bat}^{cap}$ | 储能容量(MWh) | params.json |
| $P_{bat}^{ch,max}, P_{bat}^{dis,max}$ | 储能充放电功率上限(MW) | params.json |
| $\eta_{ch}, \eta_{dis}$ | 充放电效率 | params.json |
| $SOC_{min}, SOC_{max}, SOC_{init}$ | SOC上下限与初值 | params.json |
| $price[t]$ | 分时电价(元/kWh) | params.json |
| $carbon\_factor[t]$ | 电网碳排放因子(tCO2/MWh) | params.json |
| $carbon\_price$ | 碳价(元/tCO2) | params.json |
| $feed\_in\_price$ | 余电上网价(元/kWh) | params.json |
| $batt\_wear\_cost$ | 储能充放损耗(元/kWh) | params.json |

#### 决策变量

| 变量 | 类型 | 含义 |
|------|------|------|
| $P_{grid}[t] \ge 0$ | 连续 | 电网购电功率(MW) |
| $P_{pv}^{use}[t] \ge 0$ | 连续 | 光伏实际利用功率(MW) |
| $P_{pv}^{curt}[t] \ge 0$ | 连续 | 弃光功率(MW) |
| $P_{ch}[t] \ge 0$ | 连续 | 储能充电功率(MW) |
| $P_{dis}[t] \ge 0$ | 连续 | 储能放电功率(MW) |
| $SOC[t] \ge 0$ | 连续 | 储能荷电状态(MWh) |
| $P_{elastic}[t] \ge 0$ | 连续 | **弹性任务功率(MW) ← 技术二核心** |
| $P_{cold}[t] \ge 0$ | 连续 | **温冷任务功率(MW) ← 技术二核心** |
| $u_{ch}[t] \in \{0,1\}$ | 二进制 | 充电标志 ← 技术四 |
| $u_{dis}[t] \in \{0,1\}$ | 二进制 | 放电标志 ← 技术四 |

**总计**：24×10个连续变量 + 24×2个二进制变量 = 288个变量。CBC秒解。

> 注：$P_{rigid}[t]$ 不是决策变量，是固定输入参数——刚性任务必须按预定时间执行。

#### 约束条件

**① 功率平衡约束**
$$P_{pv}^{use}[t] + P_{grid}[t] + P_{dis}[t] = P_{load}^{base}[t] + P_{ch}[t] + P_{rigid}^{demand}[t] + P_{elastic}[t] + P_{cold}[t] + P_{node}^{idle}$$

**② 光伏出力约束**
$$P_{pv}^{use}[t] + P_{pv}^{curt}[t] = P_{pv}^{avail}[t]$$

**③ 储能充放电互斥**（技术四）
$$0 \le P_{ch}[t] \le u_{ch}[t] \cdot P_{bat}^{ch,max}$$
$$0 \le P_{dis}[t] \le u_{dis}[t] \cdot P_{bat}^{dis,max}$$
$$u_{ch}[t] + u_{dis}[t] \le 1$$

**④ 储能SOC约束**（技术四）
$$SOC[t+1] = SOC[t] + \eta_{ch} \cdot P_{ch}[t] - P_{dis}[t] / \eta_{dis}$$
$$SOC[0] = SOC_{init}$$
$$SOC_{min} \cdot E_{bat}^{cap} \le SOC[t] \le SOC_{max} \cdot E_{bat}^{cap}$$
$$SOC[23] \ge SOC_{init} \quad \text{(周期结束SOC不低于初始值)}$$

**⑤ 算力节点总容量约束**
$$P_{rigid}^{demand}[t] + P_{elastic}[t] + P_{cold}[t] + P_{node}^{idle} \le P_{node}^{rated}$$

**⑥ 弹性任务日总量约束**（技术二核心）
$$\sum_{t=0}^{23} P_{elastic}[t] = E_{elastic}^{daily}$$
$$0 \le P_{elastic}[t] \le P_{elastic}^{max}[t]$$

**⑦ 温冷任务日总量约束**（技术二核心）
$$\sum_{t=0}^{23} P_{cold}[t] = E_{cold}^{daily}$$
$$0 \le P_{cold}[t] \le P_{cold}^{max}[t]$$

**⑧ 刚性任务不可调节**（技术二）
$$P_{rigid}[t] = P_{rigid}^{demand}[t] \quad \text{(固定值)}$$

**⑨ 电网购电约束**
$$0 \le P_{grid}[t] \le P_{grid}^{max}$$

#### 目标函数

$$\min Z = \sum_{t=0}^{23} \Big(C_{grid}[t] + C_{carbon}[t] + C_{curtail}[t] + C_{battery}[t]\Big)$$

其中：
- $C_{grid}[t] = P_{grid}[t] \cdot price[t]$ — 购电成本(元)
- $C_{carbon}[t] = P_{grid}[t] \cdot carbon\_factor[t] \cdot carbon\_price$ — 碳排放成本(元)
- $C_{curtail}[t] = P_{pv}^{curt}[t] \cdot feed\_in\_price$ — 弃光机会损失(元)
- $C_{battery}[t] = (P_{ch}[t] + P_{dis}[t]) \cdot batt\_wear\_cost$ — 储能损耗(元)

### 5.3 三场景定义

| 对比维度 | 场景一：无算力 | 场景二：固定算力（电随算走） | 场景三：弹性算力（算随电走） |
|----------|---------------|---------------------------|-----------------------------|
| P_rigid | 0 | P_rigid_demand[t] (固定) | P_rigid_demand[t] (固定) |
| P_elastic | 0 | E_elastic/24 均匀固定 | **MILP自动优化分配** |
| P_cold | 0 | E_cold/24 均匀固定 | **MILP自动优化分配** |
| 算力≈ | 不存在 | 被动用电，固定负荷 | **主动跟随绿电，弹性负荷** |
| 求解 | LP | LP（算力负荷固定） | MILP（算力负荷为决策变量） |

> **场景二是"电随算走"的数字孪生**：边缘节点24小时均速运行，不根据绿电波动调整。
>
> **场景三是"算随电走"的数字孪生**：MILP自动将弹性/温冷任务推到光伏高峰时段(9:00-17:00)，减少夜间算力负荷。

固定场景三参数，遍历4组储能容量：

| 组别 | E_bat_cap | 分析目的 |
|------|-----------|----------|
| 0 MWh | 无储能 | 基线：纯靠电网平抑绿电波动 |
| 3 MWh | 小储能 | 低成本方案，检验最小有效储能 |

### 5.10 预测→调度闭环验证（层三，报告新增亮点）

#### 5.10.1 目的

层一和层二验证了"算随电走"在理论上和具体场景中都有效。但存在一个缺口——MILP 的输入始终是**完美信息**（历史 GHI 通过物理模型算出的精确 PV）。

层三闭合这个缺口：**用 GRU-XGBoost 日前预测的 PV 驱动 MILP，对比"完美信息调度"和"预测信息调度"的差距**，回答——预测误差会如何影响调度质量？

#### 5.10.2 实现文件

```
文件：forecast_to_milp.py（桥接脚本，~300行）

流程：
  ① 运行 pv_forecaster 完整管线（GRU→XGBoost→36天测试集预测）
  ② 选取 3 个代表性预测日（最佳/典型/最差）
  ③ 15h 预测 → 夜间补 0 → 24h PV 曲线
  ④ 同一日分别用"实际值"和"预测值"跑 MILP 场景三
  ⑤ 对比：预测误差的调度代价

输入：
  · pv_forecaster.py 的全部函数（import 复用）
  · milp_optimizer.py 的 run_milp_scenario()（import 复用）
  · data/base_load_curves.csv

输出（outputs/forecast_milp/）：
  · metrics_comparison.csv           ← 完美 vs 预测 指标对比
  · forecast_vs_actual_3days.png     ← 三个代表性日预测 vs 实际 PV
  · forecast_error_cost.png          ← 预测误差→调度成本柱状图
  · power_balance_最佳预测.png       ← 最佳预测日功率平衡堆叠
  · power_balance_最差预测.png       ← 压力测试：预测最差的一天
```

#### 5.10.3 实验结果（2025年测试集）

| 日期 | nRMSE | 完美调度成本 | 预测调度成本 | 成本差异 | 消纳率差异 |
|------|:---:|:---:|:---:|:---:|:---:|
| 2025-08-18（最佳） | 0.0459 | 11,765 元 | 11,920 元 | +154 元 (+1.3%) | +3.1pp |
| 2025-08-26（典型） | 0.1288 | 11,728 元 | 12,716 元 | +988 元 (+8.4%) | +10.3pp |
| 2025-05-28（最差） | 0.6735 | 20,601 元 | 16,814 元 | -3,787 元 | 0.0pp |

**关键发现**：
- 当预测质量正常时（nRMSE < 0.13），预测误差的调度代价可控（+1.3%~+8.4%）
- 极端离群日（nRMSE > 0.6，日均 PV 仅 4.1MW）预测失效，系统退化为保守策略
- **即使在预测值驱动下，场景三（算随电走）的弹性调度仍然有效——正午弹性任务集中执行、夜间退避的模式未被破坏**

**零影响**。`milp_optimizer.py` 不修改任何代码。桥接脚本通过 `import` 复用其 `run_milp_scenario()` 函数，直接传入预测的 24h PV 数组。模块二的 CSV 输入接口（green_power_curves.csv、minqing_raw_days.csv）保持不变。

## 六、模块三：TOPSIS技术评价详细设计

### 6.1 文件与接口

```
文件：topsis_eval.py

输入：
  · params.json → topsis 参数段

输出：
  · outputs/topsis_ranking.png   ← 排序柱状图 + TRL气泡图
  · outputs/topsis_result.csv    ← C_i值 + 排序
```

### 6.2 算法流程

```
步骤1: 构建原始矩阵 X (5行×8列)

步骤2: 正向化 — 负向指标取倒数
       实施难度(7列): 原始值越小越好 → r = 1/x
       风险等级(8列): 原始值越小越好 → r = 1/x

步骤3: 标准化 (向量归一化)
       r_ij = x_ij / sqrt(Σ_k x_kj²)

步骤4: 加权 — 等权(各0.125)
       v_ij = w_j × r_ij

步骤5: 确定正负理想解
       A+ = (max_i v_i1, ..., max_i v_i8)
       A- = (min_i v_i1, ..., min_i v_i8)

步骤6: 计算距离
       D_i+ = sqrt(Σ_j (v_ij - A+_j)²)
       D_i- = sqrt(Σ_j (v_ij - A-_j)²)

步骤7: 计算贴近度并排序
       C_i = D_i- / (D_i+ + D_i-)
       按C_i降序排列
```

### 6.3 可视化

- **主图**：水平柱状图，5项技术的C_i值降序排列
- **副图**：TRL气泡图，X轴=TRL等级，Y轴=C_i值，气泡大小=重要性评分

模块四不是独立的AI Demo，而是**整个"算随电走"论证链条的关键一环**。它用实验数据证明：边缘AI推理任务确实可以按照刚性/弹性/温冷三级灵活调度。

### 7.5 三级任务调度对比实验

为验证"算随电走"对AI推理任务的可行性，设计三种调度模式的对比实验：

| 模式 | 调度策略 | 日间(8-17h)弹性任务占比 | 对应MILP场景 |
|------|----------|------------------------|-------------|
| 模式一：均匀调度 | 所有任务24h均匀分布 | ~42% | 场景二（电随算走） |
| 模式二：弹性调度 | 弹性+温冷任务集中在光伏高峰 | ~100% | 场景三（算随电走） |
| 模式三：纯绿电离线 | 仅在光伏>阈值时执行弹性任务 | ~100%（仅日照时段） | 极端绿电场景 |

**预期结果**：模式二（弹性调度）使日间(8-17h)AI算力功耗显著高于夜间(0-7h)，峰值功耗向光伏出力曲线对齐。这为MILP模型中P_elastic的调度自由度提供了实验层面的验证。

## 九、技术二和技术四的实现边界（澄清）

### 技术二：边缘算力负载弹性调度

在 `milp_optimizer.py` 中的实现位置：

```python
# ==========================================
# 技术二：边缘算力负载弹性调度技术
# ==========================================

# --- 决策变量 ---
# P_elastic[t], P_cold[t] 是MILP的连续决策变量
# 优化器自动决定每个小时的弹性/温冷任务量
# P_rigid[t] 是固定输入参数，不参与优化

# --- 约束⑥ 弹性任务日总量 ---
for t in range(24):
    prob += P_elastic[t] <= P_elastic_max[t]    # 每小时上限
prob += lpSum([P_elastic[t] for t in range(24)]) == E_elastic_daily  # 日总量必达

# --- 约束⑦ 温冷任务日总量 ---
for t in range(24):
    prob += P_cold[t] <= P_cold_max[t]
prob += lpSum([P_cold[t] for t in range(24)]) == E_cold_daily

# --- 约束⑧ 刚性任务 ---
# P_rigid[t] 固定值，非决策变量
# 刚性任务按时执行，不可调节

# 直观理解：
# 上午10点光伏出力8MW → MILP自动把弹性任务(工业质检)堆到10-14点
# 晚上20点光伏出力0MW → 弹性任务自动降为0，只跑刚性任务
# 这就是"算随电走"的数学表达
```

### 技术四：储能协同与关键任务保障

在 `milp_optimizer.py` 中的实现位置：

```python
# ==========================================
# 技术四：储能协同与关键任务保障技术
# ==========================================

# --- 决策变量 ---
# P_ch[t], P_dis[t], SOC[t] 是决策变量
# u_ch[t], u_dis[t] 是二进制变量(防止同时充放电)

# --- 约束③④ ---
# 储能充放电约束 + SOC连续性
# 当光伏出力 > 总负荷：储能自动充电(消纳多余绿电)
# 当光伏出力 < 总负荷且电价为峰段：储能自动放电(削峰)
# 当光伏出力=0且有关键刚性任务：储能放电保障任务不中断

# --- 敏感性分析 ---
# 遍历 E_bat_cap ∈ [0, 3, 5, 10] MWh
# 每组重新求解MILP
# 对比输出绿电消纳率、系统成本、关键任务保障率
```
